# دستورات الحاق: include، require

## ۱. ضرورت ماژولار بودن کد

هرچه برنامه بزرگ‌تر می‌شود، نگهداری همهٔ کد در یک فایل دشوارتر می‌گردد. **ماژولار بودن** یعنی تقسیم برنامه به فایل‌های کوچک‌تر و مستقل که هرکدام یک مسئولیت مشخص دارند. دستورات الحاق فایل در PHP ابزاری برای تحقق این هدف‌اند.

مزایای اصلی:

- **استفادهٔ مجدد:** یک فایل پیکربندی، هدر یا مجموعه توابع را می‌توان در چندین صفحه به کار برد.
- **نگهداری آسان‌تر:** تغییر در یک فایل، به‌طور خودکار در همهٔ صفحاتی که آن را الحاق کرده‌اند اعمال می‌شود.
- **خوانایی بهتر:** هر فایل تنها شامل منطق مربوط به خود است.
- **همکاری تیمی:** چند برنامه‌نویس می‌توانند روی فایل‌های جداگانه کار کنند.

PHP چهار ساختار برای الحاق فایل ارائه می‌دهد: `include`، `require`، `include_once` و `require_once`. این چهار ساختار در واقع **ساختارهای زبانی (Language Constructs)** هستند، نه تابع؛ به همین دلیل نیازی به پرانتز اجباری ندارند، هرچند استفاده از پرانتز مجاز است.

---

## ۲. دستور include

`include` فایل مشخص‌شده را در محل خود وارد می‌کند و محتوای آن را در همان نقطه اجرا می‌نماید. اگر فایل یافت نشود یا در حین الحاق خطایی رخ دهد، PHP یک **هشدار (Warning)** صادر می‌کند، اما اجرای اسکریپت **متوقف نمی‌شود** و ادامه می‌یابد .

**ساختار:**
```php
include 'filename.php';
// یا
include('filename.php');
```

**مثال:**

فرض کنید فایلی به نام `config.php` داریم:

```php
<?php
// config.php
$passMark = 10;
$schoolName = "Sample High School";
?>
```

و فایل اصلی:

```php
<?php
// main.php
include 'config.php';

echo "School: " . $schoolName;    // School: Sample High School
echo "<br>";
echo "Pass mark: " . $passMark;  // Pass mark: 10
?>
```

**تحلیل:** محتوای `config.php` در `main.php` وارد شده و متغیرهای آن در دسترس قرار گرفته‌اند. از منظر Scope، فایل الحاق‌شده **همان محدودهٔ فایلی را که آن را الحاق کرده** به ارث می‌برد؛ یعنی متغیرهای تعریف‌شده در آن، در سطح سراسری فایل اصلی قرار می‌گیرند.

> **نکته:** اگر `include` فایلی را پیدا نکند، هشدار صادر می‌شود و اسکریپت ادامه می‌یابد. این رفتار برای فایل‌های **غیرحیاتی** مانند بنر یا منوی اختیاری مناسب است .

---

## ۳. دستور require

`require` از نظر عملکرد **دقیقاً مانند** `include` است، اما در **مدیریت خطا** تفاوت اساسی دارد. اگر `require` نتواند فایل را الحاق کند، یک **خطای کشنده (Fatal Error)** صادر می‌کند و اجرای اسکریپت **کاملاً متوقف می‌شود** .

**ساختار:**
```php
require 'filename.php';
```

**مثال:**

```php
<?php
// main.php
require 'config.php';

echo "This line will not execute if config.php is missing.";
?>
```

اگر `config.php` وجود نداشته باشد، خروجی چیزی شبیه به این خواهد بود:

```
Fatal error: require(): Failed opening required 'config.php' ...
```

و خط `echo` **هرگز اجرا نمی‌شود**.

> **قاعدهٔ انتخاب:** برای فایل‌های **حیاتی** که بدون آن‌ها برنامه نمی‌تواند به‌درستی کار کند (مانند فایل پیکربندی، فایل توابع اصلی، یا فایل احراز هویت)، از `require` استفاده کنید. برای فایل‌های **غیرحیاتی** (مانند بنر یا محتوای اختیاری)، `include` مناسب‌تر است .

**جدول تفاوت include و require:**

| ویژگی | `include` | `require` |
|--------|-----------|-----------|
| سطح خطا در صورت نبود فایل | هشدار (Warning) | خطای کشنده (Fatal Error) |
| ادامهٔ اجرای اسکریپت | **بله** | **خیر** |
| کاربرد مناسب | فایل‌های غیرحیاتی | فایل‌های حیاتی |

## ۴. دستورات include_once و require_once

مشکل رایج در الحاق فایل، **الحاق مکرر** است. اگر فایلی که شامل **تعریف تابع** یا **تعریف کلاس** است دو بار الحاق شود، PHP خطای «تعریف مجدد» (Cannot redeclare) صادر می‌کند. برای جلوگیری از این مشکل، از `_once` استفاده می‌شود.

- `include_once` مانند `include` عمل می‌کند، اما **فقط اگر فایل قبلاً الحاق نشده باشد**، آن را الحاق می‌کند.
- `require_once` مانند `require` عمل می‌کند، اما **فقط اگر فایل قبلاً الحاق نشده باشد**، آن را الحاق می‌کند .

PHP برای تشخیص «قبلاً الحاق شده»، مسیر **واقعی (Resolved Path)** فایل را بررسی می‌کند؛ بنابراین اگر یک فایل از دو مسیر مختلف (مثلاً `./config.php` و `config.php`) الحاق شود، `_once` آن را یکسان تشخیص می‌دهد.

**ساختار:**
```php
include_once 'filename.php';
require_once 'filename.php';
```

**مثال:**

فایلی به نام `functions.php` داریم:

```php
<?php
// functions.php
function checkGrade($score, $limit = 10) {
    return ($score >= $limit) ? "Passed" : "Failed";
}
?>
```

اگر در فایل اصلی دو بار `include` (بدون `_once`) استفاده شود:

```php
<?php
include 'functions.php';
include 'functions.php';   // Fatal error: Cannot redeclare checkGrade()
?>
```

اما با `include_once`:

```php
<?php
include_once 'functions.php';
include_once 'functions.php';   // الحاق دوم نادیده گرفته می‌شود

echo checkGrade(12);   // Passed
?>
```

**تحلیل:** الحاق دوم به‌دلیل وجود `_once` انجام نمی‌شود و خطای تعریف مجدد رخ نمی‌دهد.

**جدول کامل چهار ساختار:**

| ساختار | در صورت نبود فایل | الحاق مکرر |
|---------|-------------------|-------------|
| `include` | هشدار، ادامهٔ اجرا | مجاز (ممکن است خطا ایجاد کند) |
| `require` | خطای کشنده، توقف | مجاز (ممکن است خطا ایجاد کند) |
| `include_once` | هشدار، ادامهٔ اجرا | جلوگیری می‌شود |
| `require_once` | خطای کشنده، توقف | جلوگیری می‌شود |

## ۵. مسیردهی فایل‌ها و نکات امنیتی

### مسیر مطلق و نسبی

- **مسیر نسبی (Relative):** نسبت به دایرکتوری فایل اصلی یا `include_path` تفسیر می‌شود. مانند `include 'includes/header.php';`
- **مسیر مطلق (Absolute):** از ریشهٔ سیستم فایل شروع می‌شود. مانند `require '/var/www/includes/config.php';`

برای جلوگیری از ابهام، استفاده از **مسیر مطلق** یا تعریف یک **ثابت مسیر پایه** توصیه می‌شود:

```php
<?php
define('BASE_PATH', __DIR__ . '/');
require BASE_PATH . 'includes/config.php';
?>
```

### نکات امنیتی مهم

1. **هرگز مسیر فایل را مستقیماً از ورودی کاربر نگیرید.** اگر مسیر الحاق از `$_GET` یا `$_POST` گرفته شود، مهاجم می‌تواند فایل دلخواه (حتی فایل‌های حساس سیستم) را الحاق کند. این آسیب‌پذیری **Local File Inclusion (LFI)** نام دارد.
2. **پسوند فایل را ثابت نگه دارید.** اگر ورودی کاربر فقط بخشی از نام فایل را تعیین می‌کند، پسوند را در کد ثابت کنید.
3. **از فایل‌های الحاقی حساس در برابر دسترسی مستقیم محافظت کنید.** فایل‌هایی که فقط برای الحاق در نظر گرفته شده‌اند (مانند `config.php`) نباید از طریق مرورگر مستقیماً قابل اجرا باشند. یکی از روش‌های رایج، تعریف یک ثابت نگهبان در فایل اصلی و بررسی آن در فایل الحاقی است:

```php
<?php
// main.php
define('APP_RUNNING', true);
require 'config.php';
?>
```

```php
<?php
// config.php
if (!defined('APP_RUNNING')) {
    exit('Direct access not allowed');
}
$passMark = 10;
?>
```

## ۶. مثال ۱: استفاده از آرایهٔ دوبعدی انجمنی در فایل الحاقی

در این مثال، داده‌های گروهی دانش‌آموزان و توابع پردازش آن‌ها را در یک فایل جداگانه قرار می‌دهیم و با `require_once` در فایل اصلی الحاق می‌کنیم.

**فایل `students.php`:**

```php
<?php
if (!defined('APP_RUNNING')) {
    exit('Direct access not allowed');
}

$students = [
    "s101" => ["name" => "Ali",  "score" => 18],
    "s102" => ["name" => "Sara", "score" => 9],
    "s103" => ["name" => "Reza", "score" => 12],
    "s104" => ["name" => "Mina", "score" => 7],
    "s105" => ["name" => "Omid", "score" => 15]
];

function getStatus($student, $limit = 10) {
    return ($student["score"] >= $limit) ? "Passed" : "Failed";
}

function classAverage($list) {
    $total = 0;
    foreach ($list as $student) {
        $total += $student["score"];
    }
    return $total / count($list);
}
?>
```

**فایل اصلی `index.php`:**

```php
<?php
define('APP_RUNNING', true);
require_once 'students.php';

foreach ($students as $id => $student) {
    echo $id . " | " . $student["name"] . " | "
         . $student["score"] . " | " . getStatus($student) . "<br>";
}

echo "<br>";
echo "Class average: " . classAverage($students);
?>
```

**خروجی:**
```
s101 | Ali | 18 | Passed
s102 | Sara | 9 | Failed
s103 | Reza | 12 | Passed
s104 | Mina | 7 | Failed
s105 | Omid | 15 | Passed

Class average: 12.2
```

**تحلیل:**
- فایل `students.php` هم داده‌ها و هم توابع را در خود دارد و با `APP_RUNNING` از دسترسی مستقیم محافظت می‌شود.
- `require_once` انتخاب شده است زیرا فایل **حیاتی** است (بدون داده‌ها و توابع، برنامه کار نمی‌کند) و ممکن است در آینده از چند نقطه الحاق شود.
- اگر `index.php` به اشتباه دوبار `students.php` را الحاق کند، `require_once` از خطای «تعریف مجدد تابع» جلوگیری می‌کند.

## ۷. مثال ۲: جداسازی فایل پیکربندی و استفاده در محاسبهٔ معدل

**فایل `settings.php`:**

```php
<?php
if (!defined('APP_RUNNING')) {
    exit('Direct access not allowed');
}

$passMark = 10;
$schoolTitle = "Sample High School";
?>
```

**فایل اصلی:**

```php
<?php
define('APP_RUNNING', true);
require 'settings.php';

function printHeader($title) {
    echo "<h3>" . $title . "</h3>";
}

function showResult($score, $limit) {
    $status = ($score >= $limit) ? "Passed" : "Failed";
    return $score . " -> " . $status;
}

printHeader($schoolTitle);
echo showResult(14, $passMark);   // 14 -> Passed
echo "<br>";
echo showResult(8, $passMark);    // 8 -> Failed
?>
```

**تحلیل:** `settings.php` شامل متغیرهای پیکربندی است و با `require` الحاق شده؛ زیرا بدون حد قبولی، منطق برنامه ناقص می‌ماند. توابع در همان فایل اصلی تعریف شده‌اند تا نشان داده شود الحاق فایل **الزاماً** نباید شامل توابع باشد و می‌تواند فقط داده‌های پیکربندی را در بر بگیرد.

## ۸. مثال ۳: مقایسهٔ include و require در عمل

برای درک تفاوت عملی، دو فایل را در نظر بگیرید.

**فایل اصلی با include:**

```php
<?php
include 'optional_banner.php';
echo "Page content continues.";
?>
```

اگر `optional_banner.php` وجود نداشته باشد، خروجی چیزی شبیه به این است:

```
Warning: include(optional_banner.php): Failed to open stream ...
Page content continues.
```

**فایل اصلی با require:**

```php
<?php
require 'essential_config.php';
echo "Page content continues.";
?>
```

اگر `essential_config.php` وجود نداشته باشد:

```
Fatal error: require(): Failed opening required 'essential_config.php' ...
```

و خط `echo` **اجرا نمی‌شود**.

> **نتیجه:** انتخاب بین `include` و `require` یک تصمیم **معماری** است، نه صرفاً نحوی. از خود بپرسید: «اگر این فایل نباشد، آیا برنامه هنوز می‌تواند به‌درستی کار کند؟» اگر پاسخ **خیر** است، `require` (یا `require_once`) انتخاب صحیح است.

---

## ۹. نکات کلیدی این بخش

- `include` و `require` هر دو فایل را الحاق می‌کنند، اما در مدیریت خطا متفاوت‌اند: `include` هشدار می‌دهد و ادامه می‌یابد، `require` خطای کشنده می‌دهد و متوقف می‌شود .
- `include_once` و `require_once` از الحاق مکرر یک فایل جلوگیری می‌کنند و برای فایل‌های شامل تعریف تابع یا کلاس ضروری‌اند .
- فایل‌های حیاتی (پیکربندی، توابع اصلی) را با `require_once` و فایل‌های غیرحیاتی را با `include` الحاق کنید.
- فایل الحاق‌شده **همان Scope** فایل الحاق‌کننده را به ارث می‌برد؛ متغیرهای آن در سطح سراسری فایل اصلی در دسترس‌اند.
- مسیر فایل را **هرگز** مستقیماً از ورودی کاربر نگیرید (خطر LFI).
- برای جلوگیری از دسترسی مستقیم به فایل‌های الحاقی حساس، از **ثابت نگهبان** استفاده کنید.
- استفاده از `__DIR__` یا یک ثابت مسیر پایه، از ابهام مسیرهای نسبی می‌کاهد.

## تست‌های چهارگزینه‌ای

**سؤال ۱.** اگر فایل مورد نظر `include` یافت نشود، چه اتفاقی می‌افتد؟
- الف) اسکریپت با خطای کشنده متوقف می‌شود.
- ب) یک هشدار صادر می‌شود و اسکریپت ادامه می‌یابد.
- ج) هیچ اتفاقی نمی‌افتد و فایل نادیده گرفته می‌شود.
- د) PHP به‌طور خودکار فایل را ایجاد می‌کند.

**سؤال ۲.** اگر فایل مورد نظر `require` یافت نشود، چه اتفاقی می‌افتد؟
- الف) یک هشدار صادر می‌شود و اسکریپت ادامه می‌یابد.
- ب) اسکریپت با خطای کشنده متوقف می‌شود.
- ج) فایل به‌طور خودکار ایجاد می‌شود.
- د) فقط یک پیام اطلاع‌رسانی نمایش داده می‌شود.

**سؤال ۳.** کدام ساختار از الحاق مکرر یک فایل جلوگیری می‌کند؟
- الف) `include`
- ب) `require`
- ج) `include_once`
- د) هر سه مورد

**سؤال ۴.** کدام گزینه برای الحاق یک فایل پیکربندی حیاتی مناسب‌تر است؟
- الف) `include`
- ب) `require_once`
- ج) `include_once`
- د) تفاوتی ندارد

**سؤال ۵.** خروجی قطعهٔ کد زیر چیست؟
```php
<?php
include_once 'functions.php';
include_once 'functions.php';
echo "Done";
?>
```
(فرض کنید `functions.php` فقط شامل تعریف یک تابع است.)
- الف) خطای «تعریف مجدد تابع»
- ب) `Done` دو بار چاپ می‌شود
- ج) `Done` یک بار چاپ می‌شود
- د) خطای کشنده

**سؤال ۶.** کدام ساختار در صورت نبود فایل، **هشدار** صادر می‌کند و اجرا را متوقف نمی‌کند؟
- الف) `require`
- ب) `require_once`
- ج) `include`
- د) هر دو `require` و `require_once`

**سؤال ۷.** چرا استفاده از مسیر فایل برگرفته از ورودی کاربر خطرناک است؟
- الف) سرعت اجرا را کاهش می‌دهد.
- ب) ممکن است منجر به آسیب‌پذیری Local File Inclusion (LFI) شود.
- ج) باعث خطای نحوی می‌شود.
- د) با `require_once` سازگار نیست.

**سؤال ۸.** ثابت نگهبان (`APP_RUNNING`) در فایل‌های الحاقی چه هدفی دارد؟
- الف) جلوگیری از دسترسی مستقیم به فایل الحاقی از طریق مرورگر
- ب) افزایش سرعت الحاق
- ج) جلوگیری از الحاق مکرر
- د) تعیین مسیر مطلق فایل

**سؤال ۹.** اگر فایلی که شامل تعریف تابع است، دو بار با `include` (بدون `_once`) الحاق شود، چه خطایی رخ می‌دهد؟
- الف) Warning
- ب) Fatal error: Cannot redeclare function
- ج) Notice
- د) هیچ خطایی رخ نمی‌دهد

**سؤال ۱۰.** کدام گزینه دربارهٔ Scope فایل الحاق‌شده صحیح است؟
- الف) متغیرهای فایل الحاقی در Scope محلی تابع الحاق‌کننده قرار می‌گیرند.
- ب) فایل الحاق‌شده Scope مستقل و جداگانه‌ای دارد.
- ج) فایل الحاق‌شده همان Scope فایل الحاق‌کننده را به ارث می‌برد.
- د) متغیرهای فایل الحاقی فقط با `global` قابل دسترسی‌اند.

## پاسخنامهٔ تشریحی

**۱. پاسخ: ب** — `include` در صورت نبود فایل، هشدار (Warning) صادر می‌کند اما اجرای اسکریپت ادامه می‌یابد .

**۲. پاسخ: ب** — `require` در صورت نبود فایل، خطای کشنده (Fatal Error) صادر می‌کند و اسکریپت متوقف می‌شود .

**۳. پاسخ: ج** — `include_once` (و همچنین `require_once`) با بررسی مسیر واقعی فایل، از الحاق مکرر جلوگیری می‌کند .

**۴. پاسخ: ب** — فایل پیکربندی حیاتی است؛ اگر الحاق نشود برنامه نمی‌تواند کار کند. `require_once` هم خطای کشنده می‌دهد و هم از الحاق مکرر جلوگیری می‌کند.

**۵. پاسخ: ج** — `include_once` در فراخوانی دوم، فایل را دوباره الحاق نمی‌کند و فقط یک بار `Done` چاپ می‌شود.

**۶. پاسخ: ج** — تنها `include` (و همچنین `include_once`) در صورت نبود فایل، هشدار صادر می‌کند و اجرا را متوقف نمی‌سازد؛ `require` و `require_once` خطای کشنده می‌دهند.

**۷. پاسخ: ب** — اگر مسیر الحاق از ورودی کاربر گرفته شود، مهاجم می‌تواند فایل‌های حساس سیستم را الحاق کند؛ این آسیب‌پذیری LFI نام دارد.

**۸. پاسخ: الف** — ثابت نگهبان بررسی می‌کند که فایل الحاقی فقط از طریق فایل اصلی (و نه با دسترسی مستقیم از مرورگر) اجرا شود.

**۹. پاسخ: ب** — الحاق مکرر فایلی که تابع تعریف می‌کند، منجر به خطای «تعریف مجدد تابع» می‌شود؛ `_once` برای جلوگیری از همین خطا طراحی شده است.

**۱۰. پاسخ: ج** — فایل الحاق‌شده Scope فایل الحاق‌کننده را به ارث می‌برد؛ متغیرهای آن در همان سطح سراسری فایل اصلی قرار می‌گیرند.
