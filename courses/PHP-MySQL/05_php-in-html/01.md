# بخش اول: ترکیب PHP و HTML و تولید محتوای پویا

## ۱-۱. چرا HTML به‌تنهایی کافی نیست؟

**HTML** یک زبان نشانه‌گذاری است که به مرورگر می‌گوید یک سند را چگونه نمایش دهد. HTML **زبان برنامه‌نویسی نیست**؛ نمی‌تواند محاسبه کند، شرط بسازد یا مطلبی را تکرار کند. HTML از سرور ارسال می‌شود و در مرورگر — که گاهی **کلاینت (Client)** نامیده می‌شود — تفسیر می‌گردد.

اگر محتوای سایت ثابت باشد، HTML به‌تنهایی کافی است. اما در یک **سایت پویا** — مثل وبلاگی که نوشته‌های تازه دارد یا فروشگاهی که اطلاعات محصولاتش تغییر می‌کند — محتوا باید به‌طور خودکار ساخته شود. برای این کار به ترکیب HTML و PHP نیاز داریم.

| ویژگی | HTML | PHP |
| --- | --- | --- |
| نوع زبان | نشانه‌گذاری | برنامه‌نویسی |
| محل اجرا | مرورگر (کلاینت) | وب‌سرور |
| وظیفه | نمایش سند | ساخت، دستکاری و خروجی دادن داده |
| شرط و حلقه | ندارد | دارد |
| آنچه مرورگر می‌بیند | خود سند | فقط خروجی PHP |

---

## ۱-۲. PHP کجا اجرا می‌شود؟

PHP یک زبان برنامه‌نویسی است و می‌توان از آن برای **ساختن، دستکاری و خروجی دادن داده** استفاده کرد. کد PHP روی **وب‌سرور** اجرا می‌شود و نتیجهٔ اجرای اسکریپت به مرورگر فرستاده می‌شود.

مرورگر هیچ‌وقت نمی‌فهمد که PHP داده‌ای برایش فرستاده است؛ فقط متنی را دریافت می‌کند که PHP خروجی داده است. این متن می‌تواند شامل HTML باشد، اما **هیچ کد PHP‌ای به مرورگر نمی‌رود**.

> **نکته:** وقتی در مرورگر گزینهٔ «View Source» را می‌زنید، خروجی PHP را می‌بینید، نه کد PHP را. اگر کد PHP را دیدید، یعنی فایل روی سرور اجرا نشده است (بخش ۱-۷).

---

## ۱-۳. نوشتن HTML با `echo`

دستور `echo` در PHP متن را به مرورگر می‌نویسد. پس می‌توان HTML را هم با آن تولید کرد:

```php
<?php
echo '<h1>Lorem Ipsum</h1>';
echo '<p>Hello, Dave!</p>';
?>
```

اگر سورس صفحه را در مرورگر ببینید، همهٔ خروجی `echo`ها پشت سر هم و **در یک خط** دیده می‌شود، چون در رشته‌ها شکست خط (`\n`) نگذاشته‌ایم. مرورگر به این موضوع اهمیت نمی‌دهد و HTML را در هر حالت یکسان نمایش می‌دهد.

با این حال، نوشتن HTML با رشته‌های `echo` **ناکارآمد** است، **نگهداری‌اش سخت** می‌شود و ظاهر کد **به‌هم‌ریخته** است. تا حد امکان باید HTML و PHP را از هم جدا نگه داریم.

---

## ۱-۴. پسوند فایل و فایل پیش‌فرض `index.php`

یک فایل اسکریپت باید پسوند **`.php`** داشته باشد تا وب‌سرور بداند آن را باید به مفسر PHP بدهد. اگر فایل را با پسوند `.html` ذخیره کنید، کد PHP به‌صورت متن خام به مرورگر می‌رود.

همان‌طور که فایل `index.html` در صورت نبودن نام فایل در آدرس به‌طور خودکار نمایش داده می‌شود، `index.php` هم همین رفتار را دارد:

| آدرس در مرورگر | فایلی که اجرا می‌شود |
| --- | --- |
| `http://localhost/mysite/` | `index.php` (یا `index.html`) |
| `http://localhost/mysite/index.php` | `index.php` |
| `http://localhost/mysite/page.php` | `page.php` |

---

## ۱-۵. تگ باز و بستهٔ PHP

هر قطعه کد PHP داخل تگ‌های `<?php` و `?>` قرار می‌گیرد:

```php
<?php
// کد PHP
?>
```

- در فایلی که **فقط** کد PHP دارد، تنها تگ باز لازم است و گذاشتن `?>` توصیه نمی‌شود؛ چون فاصله یا خط خالی بعد از آن می‌تواند به‌اشتباه به مرورگر ارسال شود.
- تگ بستهٔ `?>` زمانی استفاده می‌شود که PHP و HTML را **ترکیب** می‌کنیم.

**تگ کوتاه چاپ مقدار:**

اگر تنها کار شما داخل تگ‌ها `echo` است، می‌توانید از تگ کوتاه `<?=` استفاده کنید:

```php
<p>Hello, <?= $name; ?>!</p>
```

این خط دقیقاً معادل کد زیر است و خروجی یکسانی دارد:

```php
<p>Hello, <?php echo $name; ?>!</p>
```

**تگ باز کوتاه `<?`** — نسخهٔ کوتاه‌شدهٔ تگ باز — استفاده از آن **توصیه نمی‌شود**؛ چون باید در تنظیمات PHP به‌صورت صریح فعال شود و مزیتی جز کوتاه‌تر بودن کد ندارد. (استاندارد PSR-1 نیز استفاده از آن را منع می‌کند.)

> **دقت کنید:** `<?=` با `<?` فرق دارد. اولی همیشه در دسترس است و فقط برای چاپ مقدار به کار می‌رود؛ دومی همان تگ باز است که فعال‌سازی می‌خواهد.

## ۱-۶. مثال کامل: یک صفحهٔ پویا

فایل `index.php`:

```php
<?php

$name = "Dave";

?>
<!DOCTYPE html>
<html>
<head>
    <title>My website</title>
    <meta charset="utf-8">
</head>
<body>

    <h1>Lorem Ipsum</h1>

    <p>Hello, <?= $name; ?>!</p>

</body>
</html>
```

**چه اتفاقی می‌افتد؟**

1. وب‌سرور فایل را می‌گیرد و بخش PHP بالای صفحه را اجرا می‌کند. آنجا فقط مقدار `Dave` در متغیر `$name` قرار می‌گیرد و **هیچ خروجی‌ای تولید نمی‌شود**، چون `echo` وجود ندارد.
2. HTML به همان شکل به مرورگر فرستاده می‌شود.
3. در خط `<?= $name; ?>` مقدار متغیر چاپ می‌شود و تگ‌های باز و بسته همراه با خودِ کد حذف می‌شوند.
4. مرورگر در نهایت فقط HTML زیر را دریافت می‌کند:

```html
<p>Hello, Dave!</p>
```

> **نکته:** در سورس صفحه هیچ اثری از `$name`، `<?php` یا `?>` نیست. تنها متن `Dave` باقی مانده است.

## ۱-۷. اشتباه‌های رایج

| مشکل | علت احتمالی | راه‌حل |
| --- | --- | --- |
| کد PHP در مرورگر دیده می‌شود | فایل با پسوند `.html` ذخیره شده یا با `file://` باز شده است | پسوند را `.php` کنید و صفحه را از `http://localhost/...` باز کنید |
| خروجی رشته‌های `echo` در یک خط است | شکست خط در رشته‌ها نگذاشته‌اید | با `\n` یا با جداسازی HTML از PHP این کار را انجام دهید |
| خطای Parse error | فراموشی `?>`، `;` یا ناهماهنگی تگ‌ها | تگ‌های باز/بسته و سمیکالن‌ها را بررسی کنید |
| صفحهٔ سفید بدون پیام | خطای PHP و خاموش بودن نمایش خطاها | نمایش خطاها (`display_errors`) را روشن کنید و لاگ Apache را ببینید |

---

## خلاصه نکات کلیدی

1. HTML زبان نشانه‌گذاری برای نمایش است و در **مرورگر** تفسیر می‌شود؛ PHP زبان برنامه‌نویسی است و روی **سرور** اجرا می‌شود.
2. برای ساخت محتوای پویا باید HTML و PHP را ترکیب کرد.
3. **هیچ کد PHP‌ای به مرورگر نمی‌رود**؛ مرورگر فقط خروجی (متن و HTML) را دریافت می‌کند.
4. فایل PHP باید پسوند `.php` داشته باشد تا وب‌سرور آن را اجرا کند.
5. `index.php` در صورت نبودن نام فایل در آدرس، به‌طور خودکار اجرا می‌شود.
6. تگ بستهٔ `?>` فقط هنگام ترکیب PHP با HTML لازم است؛ در فایلِ فقط‌PHP حذف آن بهتر است.
7. `<?= $name; ?>` معادل `<?php echo $name; ?>` است.
8. تگ باز کوتاه `<?` توصیه نمی‌شود؛ باید صریحاً فعال شود و مزیت واقعی ندارد.
9. تولید حجم زیاد HTML با `echo` ناکارآمد است؛ HTML و PHP را تا حد امکان جدا نگه دارید.
10. اگر کد PHP را در صفحه دیدید، یعنی فایل روی سرور اجرا نشده است.

## ۱۰ سؤال تستی

### سؤال ۱

HTML چه نوع زبانی است؟

- الف) زبان برنامه‌نویسی سمت سرور
- ب) زبان نشانه‌گذاری برای نمایش سند
- ج) زبان مدیریت پایگاه داده
- د) زبان پیکربندی وب‌سرور

### سؤال ۲

کد PHP در معماری وب در کجا اجرا می‌شود؟

- الف) در مرورگر کاربر
- ب) در ویرایشگر کد
- ج) روی وب‌سرور
- د) در فایل CSS

### سؤال ۳

مرورگر از یک صفحهٔ PHP چه چیزی دریافت می‌کند؟

- الف) کد PHP خام
- ب) فقط خروجی PHP (متن و HTML)
- ج) فایل پیکربندی PHP
- د) کد PHP و HTML به‌صورت جداگانه

### سؤال ۴

برای اینکه وب‌سرور فایل را به مفسر PHP بدهد، فایل باید چه پسوندی داشته باشد؟

- الف) `.html`
- ب) `.php`
- ج) `.txt`
- د) `.css`

### سؤال ۵

اگر در آدرس فقط `http://localhost/mysite/` وارد شود و نام فایلی ذکر نشود، کدام فایل به‌طور خودکار اجرا می‌شود؟

- الف) `page.php`
- ب) `wp-config.php`
- ج) `index.html` یا `index.php`
- د) `config.php`

### سؤال ۶

کدام گزینه معادل `<p>Hello, <?= $name; ?>!</p>` است؟

- الف) `<p>Hello, <?php echo $name; ?>!</p>`
- ب) `<p>Hello, <?php $name; ?>!</p>`
- ج) `<p>Hello, $name!</p>`
- د) `<p>Hello, <? $name ?></p>`

### سؤال ۷

دربارهٔ تگ باز کوتاه `<?` کدام گزینه صحیح است؟

- الف) همیشه فعال است و استفاده از آن توصیه می‌شود.
- ب) فقط برای چاپ مقدار به کار می‌رود.
- ج) باید صریحاً فعال شود و استفاده از آن توصیه نمی‌شود.
- د) هیچ تفاوتی با `<?php` ندارد و در همهٔ سرورها کار می‌کند.

### سؤال ۸

در فایلی که فقط کد PHP دارد، دربارهٔ تگ بستهٔ `?>` کدام گزینه صحیح است؟

- الف) حتماً باید نوشته شود.
- ب) بهتر است حذف شود تا فاصله‌های اضافی به مرورگر نرود.
- ج) فقط با تگ باز کوتاه کار می‌کند.
- د) جای `<?php` را می‌گیرد.

### سؤال ۹

دلیل دیده شدن کد PHP در مرورگر چیست؟

- الف) PHP روی سرور نصب نیست.
- ب) فایل اجرا نشده است؛ مثلاً پسوند `.html` دارد یا با `file://` باز شده است.
- ج) مرورگر از PHP پشتیبانی نمی‌کند.
- د) متغیرها مقداردهی نشده‌اند.

### سؤال ۱۰

چرا نوشتن حجم زیاد HTML با دستور `echo` توصیه نمی‌شود؟

- الف) مرورگر آن را نمایش نمی‌دهد.
- ب) PHP از رشته‌های طولانی پشتیبانی نمی‌کند.
- ج) ناکارآمد است، کد به‌هم‌ریخته می‌شود و نگهداری آن سخت است.
- د) باعث اجرای دوبارهٔ اسکریپت می‌شود.

| سؤال | گزینهٔ درست | توضیح کوتاه |

| ۱ | ب | HTML برای نشانه‌گذاری و نمایش سند است، نه برنامه‌نویسی. |
| ۲ | ج | PHP سمت سرور اجرا می‌شود و نتیجه را می‌فرستد. |
| ۳ | ب | فقط خروجی PHP به مرورگر می‌رسد؛ کد اجرا و حذف می‌شود. |

| ۵ | ج | فایل پیش‌فرض پوشه، `index.php` یا `index.html` است. |
| ۶ | الف | `<?=` شکل کوتاه `echo` است و خروجی یکسانی دارد. |
| ۷ | ج | `<?` نیازمند فعال‌سازی است و استانداردها آن را نمی‌پسندند. |

| ۱۰ | ج | جداسازی HTML از PHP خواناتر، سریع‌تر و قابل‌نگهداری‌تر است. |
