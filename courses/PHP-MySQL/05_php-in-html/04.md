# بخش چهارم: کامنت‌ها و استانداردهای کدنویسی PHP

## ۴-۱. چرا کد PHP باید خوانا باشد؟

کد PHP فقط برای اجرا نوشته نمی‌شود؛ **دیگران** (و خودِ شما چند ماه بعد) آن را می‌خوانند و تغییر می‌دهند. دو ابزار اصلی برای خوانایی PHP:

1. **کامنت‌ها** برای توضیح بخش‌هایی که از خود کد فهمیده نمی‌شوند.
2. **فاصله‌گذاری و استانداردهای کدنویسی** برای یکدست و مرتب بودن ظاهر کد.

---

## ۴-۲. دو روش کامنت در PHP

**روش اول: کامنت تک‌خطی با `//`**

هر چیزی از `//` تا **پایان همان خط** کامنت است:

```php
<?php
// این یک کامنت در یک خط مستقل است
$price = 1000;   // توضیح کنار کد: قیمت پایه

$total = $price * 2; // محاسبهٔ قیمت دو عدد
?>
```

**روش دوم: کامنت چندخطی با `/* ... */`**

کامنت با `/*` شروع و با `*/` تمام می‌شود و می‌تواند **چند خط** باشد:

```php
<?php
/*
  این بلوک چند خطی است.
  برای توضیح یک بخش کامل مناسب است.
*/
$discount = 0.2;
?>
```

> **نکته:** روش سوم با `#` نیز در PHP وجود دارد و مثل `//` تا پایان خط ادامه می‌یابد، اما در کدهای امروزی کمتر استفاده می‌شود. در ادامهٔ درس روی دو روش اصلی تمرکز می‌کنیم.

بیشتر ویرایشگرها کامنت‌ها را با **رنگ متفاوت** نشان می‌دهند تا سریع از کد جدا شوند.

---

## ۴-۳. تفاوت مهم: کامنت PHP به مرورگر نمی‌رسد

کامنت HTML **در سورس صفحه دیده می‌شود**، اما کامنت PHP **اصلاً به مرورگر فرستاده نمی‌شود**. دلیلش روشن است: همهٔ کد PHP قبل از ارسال پاسخ، روی سرور اجرا می‌شود و کامنت هم بخشی از کد PHP است؛ در نتیجه همراه با خود کد حذف می‌شود.

```php
<?php
// این خط در سورس صفحه دیده نمی‌شود
echo "Hello";
?>
```

خروجی در مرورگر:

```
Hello
```

> **نتیجه:** می‌توانید با خیال راحت در کد PHP توضیح بنویسید؛ برخلاف کامنت HTML، کاربر آن را نمی‌بیند. البته این مجوزی برای نوشتن رمز عبور یا کلید در کامنت نیست — کد سرور هم ممکن است در دسترس افراد غیرمجاز قرار گیرد.

---

## ۴-۴. کامنت چه زمانی لازم است؟

کامنت وقتی ارزش دارد که **کد به‌تنهایی گویا نباشد**. اگر کد روشن است، کامنت اضافی فقط شلوغی ایجاد می‌کند:

```php
<?php
// ❌ کامنت غیرضروری: کد خودش مشخص است
// افزایش شمارنده
$counter++;

// ✅ کامنت مفید: دلیل تصمیم را توضیح می‌دهد
// مالیات فقط برای سفارش‌های بالای ۵ میلیون اعمال می‌شود
if ($total > 5000000) {
    $total += $total * 0.09;
}
?>
```

**قاعده:** کامنت بگویید **چرا**، نه **چه**. توضیح «این خط چه می‌کند» معمولاً تکراری است؛ توضیح «چرا این‌گونه نوشته شده» ارزشمند است.

---

## ۴-۵. نام‌گذاری معنادار، جایگزین بخشی از کامنت‌ها

اگر نام متغیرها و توابع معنادار باشند، بسیاری از کامنت‌ها لازم نمی‌شوند:

| ضعیف | بهتر |
| --- | --- |
| `$x` | `$totalPrice` |
| `$a` | `$articles` |
| `$d` | `$discountPercent` |
| `f1()` | `calculateTotal()` |

با نام‌گذاری درست، خواننده بدون کامنت هم منظور کد را می‌فهمد.

---

## ۴-۶. فاصله‌گذاری در کد PHP

مثل HTML، در PHP هم فاصله، تب و شکست خط روی **اجرای برنامه اثری ندارند**، اما روی **خوانایی** اثر زیادی دارند. مثلاً این خط:

```php
<?php
$articles=["First post","Another post","Read this!"];
?>
```

درست کار می‌کند، اما خواندنش سخت است. نسخهٔ مرتب و خوانا:

```php
<?php
$articles = ["First post", "Another post", "Read this!"];
?>
```

قواعد ساده:

- دو طرف عملگرها فاصله بگذارید: `$a = $b + 1;` نه `$a=$b+1;`.
- بعد از کاما فاصله بگذارید: `f($a, $b)` نه `f($a,$b)`.
- هر دستور را در خط خودش بنویسید.
- بدنهٔ بلوک‌ها را تودرتو کنید.

## ۴-۷. استانداردهای کدنویسی PSR

PHP برخلاف HTML، **استانداردهای توصیه‌شدهٔ رسمی** برای نوشتن کد دارد که با نام **PSR** شناخته می‌شوند (PHP Standards Recommendations):

| استاندارد | موضوع |
| --- | --- |
| **PSR-1** | استانداردهای پایهٔ کدنویسی؛ مثل پرهیز از تگ باز کوتاه `<?` و قواعد نام‌گذاری |
| **PSR-2** | سبک کدنویسی؛ مثل تعداد فاصله برای تورفتگی (۴ فاصله)، محل آکولادها، طول خط |
| **PSR-12** | نسخهٔ کامل‌تر و امروزی‌تر سبک کدنویسی (جانشین PSR-2) |

در عمل، **پیروی از PSR-2** (و امروزه PSR-12) رایج‌ترین سطح استاندارد است. رعایت این قواعد باعث می‌شود:

- کد شما برای هر برنامه‌نویس PHP **آشنا و قابل‌خواندن** باشد.
- هنگام کار تیمی، تفاوت سبک‌ها مشکل ایجاد نکند.
- خواندن کد دیگران برای شما آسان‌تر شود.

مثال تورفتگی ۴ فاصله‌ای طبق PSR-2:

```php
<?php
if ($isLoggedIn) {
    echo "Welcome";
} else {
    echo "Please log in";
}
?>
```

## ۴-۸. ابزارهای اصلاح خودکار کد

برای اینکه کد مطابق PSR-2 باشد، لازم نیست همهٔ قواعد را حفظ کنید:

- **فرمت‌کننده‌های آنلاین** وجود دارند که کد PHP را مطابق PSR-2 مرتب می‌کنند.
- ابزار خط فرمان **PHP Coding Standards Fixer (PHP CS Fixer)** را می‌توان دانلود و روی فایل اجرا کرد:

```bash
php-cs-fixer fix index.php
```

این برنامه کد را بازقالب‌بندی می‌کند تا با استاندارد PSR-2 سازگار شود. با این حال، اگر قواعد را بشناسید، می‌توانید **از همان ابتدا** کد تمیز بنویسید و به ابزار اصلاح نیاز پیدا نکنید.

> **نکته:** کدهای ارائه‌شده در این دوره با استاندارد PSR-2 سازگارند.

## ۴-۹. مثال کامل

کد زیر فهرست مقاله‌ها را چاپ می‌کند، ابتدا بدون رعایت نکات خوانایی و سپس با رعایت آن‌ها:

```php
<?php
$articles=["First post","Another post","Read this!"];

foreach ($articles as $article) {
    echo $article, ", ";
}
?>
```

نسخهٔ خوانا و استاندارد:

```php
<?php

// فهرست عنوان مقاله‌ها
$articles = ["First post", "Another post", "Read this!"];

foreach ($articles as $article) {
    echo $article, ", ";
}
```

خروجی هر دو یکسان است:

```
First post, Another post, Read this!,
```

> **نکتهٔ تکمیلی:** برای چسباندن اعضای آرایه با جداکننده، تابع `implode` خواناتر از حلقه و `echo` است؛ هرچند نتیجهٔ نهایی‌اش کاما در انتها ندارد:
>
> ```php
> echo implode(", ", $articles);
> ```

## خلاصه نکات کلیدی

1. در PHP دو روش اصلی کامنت وجود دارد: `//` برای یک خط و `/* ... */` برای چند خط.
2. کامنت `//` تا پایان همان خط ادامه دارد؛ حتی می‌تواند کنار یک دستور بیاید.
3. **کامنت PHP به مرورگر فرستاده نمی‌شود**، برخلاف کامنت HTML که در سورس دیده می‌شود.
4. دلیل این تفاوت آن است که کل کد PHP (و کامنت‌هایش) قبل از ارسال، روی سرور اجرا و حذف می‌شود.
5. کامنت را وقتی بنویسید که کد خودگویا نیست؛ توضیح «چرا» بهتر از توضیح «چه» است.
6. نام‌گذاری معنادار متغیرها و توابع، نیاز به بسیاری از کامنت‌ها را از بین می‌برد.
7. فاصله، تب و شکست خط روی اجرای PHP اثر ندارند، اما خوانایی را به‌شدت تغییر می‌دهند.
8. استانداردهای PHP با نام **PSR** شناخته می‌شوند؛ **PSR-1** پایه و **PSR-2** سبک کدنویسی را تعریف می‌کند.
9. پرهیز از تگ باز کوتاه `<?` یکی از توصیه‌های PSR-1 است.
10. ابزارهایی مثل **PHP CS Fixer** و فرمت‌کننده‌های آنلاین، کد را خودکار با PSR-2 سازگار می‌کنند.
