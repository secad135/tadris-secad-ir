# موضوع اول: منطق بررسی ارسال فرم، روش ارسال و وجود یک مقدار

## خلاصه مطالب

### ۱. چرا به این بررسی‌ها نیاز داریم؟

یک صفحه PHP می‌تواند به دو شکل باز شود:

- **حالت اول:** کاربر تازه صفحه را باز کرده و هنوز فرمی نفرستاده است.
- **حالت دوم:** کاربر فرم را پر کرده و دکمه ثبت را زده است.

اگر در کد PHP مستقیم بنویسیم `$_POST['name']` و صفحه در حالت اول باز شود، آن کلید وجود ندارد و PHP هشدار (Warning) نشان می‌دهد. پس باید بدانیم:

- آیا فرم اصلاً ارسال شده است؟
- با چه روشی ارسال شده است؟
- آیا آن مقدار خاص وجود دارد؟

این سه بررسی، پایه هر برنامه‌ای است که با فرم کار می‌کند.

### ۲. بررسی ارسال فرم — روش اول: نام روی دکمه ثبت

ساده‌ترین روش این است که روی دکمه ثبت یک `name` بگذاریم و در PHP وجود آن را بررسی کنیم.

**در HTML:**

```html
<button type="submit" name="submit">Send</button>
```

**در PHP:**

```php
<?php
if (isset($_POST['submit'])) {
    echo "Form was submitted.";
} else {
    echo "Please fill the form.";
}
?>
```

وقتی کاربر دکمه را می‌زند، کلیدی به نام `submit` به داده‌ها اضافه می‌شود. اگر صفحه تازه باز شده باشد، این کلید وجود ندارد. پس `isset` در حالت اول `false` و در حالت دوم `true` است.

### ۳. بررسی ارسال فرم — روش دوم: بررسی روش درخواست

PHP روش ارسال را در متغیری به نام `$_SERVER['REQUEST_METHOD']` نگه می‌دارد. مقدار آن رشته‌ای مانند `GET` یا `POST` است.

```php
<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    echo "Form was submitted with POST.";
}
?>
```

این روش وقتی مفید است که بخواهیم بدانیم روش ارسال چه بوده است.

### ۴. فهمیدن روش ارسال

همان متغیر `$_SERVER['REQUEST_METHOD']` روش ارسال را می‌گوید:

```php
<?php
$method = $_SERVER['REQUEST_METHOD'];
echo "Method: " . $method;
?>
```

اگر فرم با `method="post"` باشد، خروجی `POST` است. اگر با `method="get"` باشد، خروجی `GET` است.

### ۵. بررسی وجود یک مقدار خاص

سه تابع پرکاربرد داریم که تفاوت‌های مهمی دارند:

**الف) `isset()`** — بررسی می‌کند که آیا کلید وجود دارد و مقدارش `null` نیست.

```php
<?php
if (isset($_POST['fullname'])) {
    echo "fullname exists.";
}
?>
```

**ب) `empty()`** — بررسی می‌کند که آیا کلید وجود ندارد **یا** مقدارش خالی است. مقدارهای خالی از نظر PHP: `""` (رشته خالی)، `0`، `"0"`، `null`، `false` و آرایه خالی.

```php
<?php
if (empty($_POST['fullname'])) {
    echo "fullname is missing or empty.";
}
?>
```

**پ) `array_key_exists()`** — بررسی می‌کند که آیا کلید وجود دارد، حتی اگر مقدارش `null` باشد.

```php
<?php
if (array_key_exists('fullname', $_POST)) {
    echo "fullname key exists.";
}
?>
```

**قاعده ساده برای دانش‌آموز:**

- برای «آیا وجود دارد؟» از `isset` استفاده کنید.
- برای «آیا وجود دارد و خالی نیست؟» از `!empty` استفاده کنید.

### ۶. استفاده ترکیبی در فرم

بهترین حالت برای هر داده این است که هم وجود داشته باشد و هم خالی نباشد:

```php
<?php
if (isset($_POST['fullname']) && !empty($_POST['fullname'])) {
    $name = $_POST['fullname'];
    echo "Name: " . $name;
} else {
    echo "Name is missing.";
}
?>
```

**توضیح ساده:** اگر کلید `fullname` وجود داشت و مقدارش خالی نبود، آن را برمی‌داریم و نمایش می‌دهیم. در غیر این صورت، پیام مناسب می‌دهیم.

### ۷. دیدن مقدارها برای رفع اشکال

برای اینکه ببینیم چه چیزی به صفحه رسیده، از `var_dump` استفاده می‌کنیم:

```php
<?php
var_dump($_POST);
?>
```

این کار در مرحله یادگیری و هنگام رفع اشکال بسیار مفید است.

### ۸. چرا این‌ها را یاد می‌گیریم؟

- **جلوگیری از هشدارها:** وقتی کلید وجود ندارد، PHP هشدار می‌دهد.
- **جلوگیری از پردازش فرم خالی:** اگر داده‌ای نیامده، نباید آن را پردازش کنیم.
- **تفکیک حالت باز کردن صفحه از حالت ارسال فرم:** این کار به نمایش درست صفحه کمک می‌کند.
- **تشخیص روش ارسال:** می‌توانیم بدانیم داده از GET آمده یا POST.

### ۹. راهکار نمایش مقدارها

برای نمایش داده‌ای که از کاربر آمده، ابتدا وجودش را بررسی می‌کنیم و سپس با تابع مناسب ایمن‌سازی می‌کنیم. تابع مناسب (`htmlspecialchars`) در موضوع بعدی به‌طور کامل معرفی می‌شود.

## ده پرسش چهارگزینه‌ای

**۱.** چرا باید بررسی کنیم که فرم ارسال شده است یا نه؟
- الف) چون PHP بدون این بررسی کار نمی‌کند
- ب) چون در حالت باز شدن تازه صفحه، داده‌ها وجود ندارند و ممکن است هشدار ایجاد شود
- پ) چون فرم بدون این بررسی ارسال نمی‌شود
- ت) هیچ دلیلی ندارد

**۲.** کدام روش برای بررسی ارسال فرم رایج‌تر است؟
- الف) گذاشتن `name` روی دکمه ثبت و بررسی با `isset`
- ب) بررسی رنگ دکمه
- پ) بررسی نوار آدرس مرورگر
- ت) استفاده از `echo`

**۳.** متغیر `$_SERVER['REQUEST_METHOD']` چه چیزی نگه می‌دارد؟
- الف) نام سرور
- ب) روش ارسال درخواست (GET یا POST)
- پ) نام کاربر
- ت) حجم داده‌ها

**۴.** کدام تابع بررسی می‌کند که آیا کلید در آرایه وجود دارد (و مقدارش `null` نیست)؟
- الف) `empty`
- ب) `isset`
- پ) `echo`
- ت) `var_dump`

**۵.** کدام تابع بررسی می‌کند که کلید وجود ندارد **یا** مقدارش خالی است؟
- الف) `isset`
- ب) `empty`
- پ) `array_key_exists`
- ت) `count`

**۶.** اگر کلید `fullname` در `$_POST` وجود داشته باشد ولی مقدارش رشته خالی `""` باشد، کدام گزاره درست است؟
- الف) `isset` مقدار `false` می‌دهد و `empty` مقدار `true`
- ب) `isset` مقدار `true` می‌دهد و `empty` مقدار `true`
- پ) هر دو `false` می‌دهند
- ت) هر دو `true` می‌دهند

**۷.** برای دیدن محتوای آرایه `$_POST` هنگام رفع اشکال از چه تابعی استفاده می‌کنیم؟
- الف) `echo`
- ب) `print`
- پ) `var_dump`
- ت) `empty`

**۸.** کدام شرط بررسی می‌کند که کلید `name` در `$_POST` وجود دارد **و** مقدارش خالی نیست؟
- الف) `if (isset($_POST['name']))`
- ب) `if (!empty($_POST['name']))`
- پ) `if (empty($_POST['name']))`
- ت) `if ($_POST['name'] == "")`

**۹.** اگر صفحه PHP تازه باز شده باشد و ما بدون بررسی از `$_POST['name']` استفاده کنیم، چه ممکن است رخ دهد؟
- الف) مقدار خالی برمی‌گردد بدون هیچ هشداری
- ب) ممکن است هشدار (Warning) نمایش داده شود
- پ) برنامه همیشه کاملاً متوقف می‌شود
- ت) مرورگر بسته می‌شود

**۱۰.** اگر فرمی با `method="get"` ارسال شود، مقدار `$_SERVER['REQUEST_METHOD']` چیست؟
- الف) `GET`
- ب) `POST`
- پ) `FORM`
- ت) خالی
