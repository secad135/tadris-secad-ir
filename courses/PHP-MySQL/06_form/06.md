# امنیت فرم‌ها به زبان ساده

## خلاصه مطالب

### ۱. چرا امنیت فرم مهم است؟

فرض کنید در مدرسه یک صندوق پیشنهادات گذاشته‌اید. هر کسی می‌تواند کاغذی داخل آن بیندازد. حالا اگر کسی به‌جای پیشنهاد، یک ترقه داخل صندوق بیندازد چه می‌شود؟ صندوق می‌سوزد!

فرم‌های وب هم همین‌طور هستند. هر کسی می‌تواند در آن‌ها چیزی بنویسد. اگر ما آن چیزی که نوشته را بدون بررسی قبول کنیم، ممکن است به سایت ما آسیب بزند.

**قاعده طلایی:** به هیچ داده‌ای که از کاربر می‌آید اعتماد نکنید.

### ۲. چهار حمله رایج که باید بشناسیم

**حمله اول: XSS — تزریق کد در صفحه**

فرض کنید یک فرم نظرخواهی داریم. کاربر عادی می‌نویسد: «این پست خیلی خوب بود.»

اما یک کاربر خرابکار می‌نویسد:

```
<script>alert('hacked')</script>
```

اگر ما این متن را بدون بررسی در صفحه نمایش دهیم، کد JavaScript اجرا می‌شود. این کد می‌تواند کوکی کاربران دیگر را بدزدد یا صفحه را به هم بریزد.

**تشبیه ساده:** مثل این است که کسی در دفتر نظرات مدرسه، به‌جای جمله، یک دستورالعمل بنویسد: «هر کسی این را خواند، کیفش را بدهد!» اگر ما این دستور را جدی بگیریم، ضرر می‌کنیم.

**حمله دوم: SQL Injection — تزریق دستور در پایگاه داده**

فرض کنید فرم ورود داریم. کاربر عادی نام کاربری می‌نویسد: `ali`.

اما کاربر خرابکار در کادر نام کاربری می‌نویسد:

```
' OR '1'='1
```

اگر ما این داده را مستقیم در دستور پایگاه داده بگذاریم، ممکن است بدون رمز عبور وارد شود.

**تشبیه ساده:** مثل این است که به نگهبان مدرسه بگویید «من علی هستم» و او بدون پرسیدن مدرک، اجازه ورود بدهد. حالا کسی می‌آید و می‌گوید «من هر کسی هستم که بخواهم باشم» و نگهبان می‌گوید «باشه، بیا داخل!»

**حمله سوم: CSRF — فریب کاربر لاگین‌شده**

فرض کنید شما در سایت مدرسه وارد شده‌اید. یک سایت دیگر (که مال یک خرابکار است) صفحه‌ای دارد که به‌طور مخفیانه به سایت مدرسه درخواست می‌فرستد: «حساب کاربری من را حذف کن!»

چون شما در سایت مدرسه وارد شده‌اید، سایت مدرسه فکر می‌کند خودتان این درخواست را فرستاده‌اید و حساب شما حذف می‌شود!

**تشبیه ساده:** مثل این است که کسی از طرف شما یک نامه امضا و به مدیر مدرسه بدهد و مدیر فکر کند خودتان نوشته‌اید.

**حمله چهارم: آپلود فایل خطرناک**

فرض کنید فرم آپلود عکس داریم. کاربر عادی عکس می‌فرستد. خرابکار فایلی می‌فرستد که اسمش `photo.jpg` است ولی در واقع یک فایل PHP است. اگر سرور آن را اجرا کند، خرابکار می‌تواند سایت را کنترل کند.

**تشبیه ساده:** مثل این است که کسی جعبه‌ای با برچسب «شکلات» بفرستد، ولی داخلش چیز خطرناکی باشد.

### ۳. ابزارهای دفاعی — ساده و کاربردی

#### ابزار اول: `htmlspecialchars()` — سپر اصلی در برابر XSS

این تابع نویسه‌های خطرناک را «بی‌خطر» می‌کند. مثلاً `<` را به `&lt;` تبدیل می‌کند که در صفحه به‌صورت متن دیده می‌شود، نه کد.

**مثال قبل از محافظت (خطرناک):**

```php
<?php
$comment = $_POST['comment'];
echo $comment;
?>
```

اگر کاربر `<script>alert('hacked')</script>` بفرستد، این کد اجرا می‌شود.

**مثال با محافظت (امن):**

```php
<?php
$comment = htmlspecialchars($_POST['comment']);
echo $comment;
?>
```

حالا همان کد، در صفحه به‌صورت متن ساده `<script>alert('hacked')</script>` دیده می‌شود، بدون اینکه اجرا شود.

**قاعده ساده:** هر چیزی که از کاربر می‌آید و می‌خواهیم نشان دهیم، **همیشه** از `htmlspecialchars()` عبور دهیم.

#### ابزار دوم: `trim()` — حذف فاصله‌های اضافی

کاربر ممکن است اشتباهی فاصله بزند. `trim()` فاصله‌های اول و آخر را حذف می‌کند.

**مثال کاربردی:** فرم ثبت نام. اگر کاربر به‌جای `Ali` نوشت `  Ali  `، بعداً موقع جستجو در پایگاه داده پیدا نمی‌شود. `trim` این مشکل را حل می‌کند.

```php
<?php
$name = trim($_POST['name']);
?>
```

#### ابزار سوم: `filter_var()` — بررسی درستی داده

این تابع بررسی می‌کند که آیا داده، شکل درستی دارد یا نه. مثلاً آیا ایمیل واقعاً ایمیل است؟

**مثال کاربردی — بررسی ایمیل:**

```php
<?php
$email = trim($_POST['email']);

if (filter_var($email, FILTER_VALIDATE_EMAIL) === false) {
    echo "Please enter a valid email.";
} else {
    echo "Email is valid.";
}
?>
```

اگر کاربر `ali@example.com` بفرستد، پیام «ایمیل درست است» می‌آید. اگر `ali@` بفرستد، پیام خطا می‌آید.

**چند فیلتر پرکاربرد:**

- `FILTER_VALIDATE_EMAIL` — بررسی ایمیل
- `FILTER_VALIDATE_INT` — بررسی عدد صحیح
- `FILTER_VALIDATE_URL` — بررسی نشانی اینترنتی
- `FILTER_SANITIZE_NUMBER_INT` — حذف همه نویسه‌ها به‌جز رقم

**مثال کاربردی — بررسی سن:**

```php
<?php
$age = filter_var($_POST['age'], FILTER_VALIDATE_INT);

if ($age === false || $age < 10 || $age > 100) {
    echo "Age must be a number between 10 and 100.";
} else {
    echo "Age: " . $age;
}
?>
```

اینجا هم بررسی کردیم که عدد است، هم اینکه در بازه درست قرار دارد.

#### ابزار چهارم: پرس‌وجوی آماده — سپر در برابر SQL Injection

به‌جای اینکه داده کاربر را مستقیم در دستور SQL بگذاریم، از پرس‌وجوی آماده استفاده می‌کنیم.

**نادرست (خطرناک):**

```php
<?php
$name = $_POST['name'];
$sql = "SELECT * FROM students WHERE name = '$name'";
?>
```

اگر کاربر `' OR '1'='1` بفرستد، دستور SQL خراب می‌شود.

**درست (امن):**

```php
<?php
$stmt = $pdo->prepare("SELECT * FROM students WHERE name = ?");
$stmt->execute([$_POST['name']]);
$result = $stmt->fetchAll();
?>
```

علامت `?` جای داده را نگه می‌دارد. PHP خودش داده را به شکل امن جای‌گذاری می‌کند. جزئیات کامل این روش در درس پایگاه داده خواهد آمد؛ در این درس فقط بدانید که همیشه از پرس‌وجوی آماده استفاده کنید.

#### ابزار پنجم: توکن CSRF — سپر در برابر فرم جعلی

برای اینکه مطمئن شویم فرم از سایت خودمان آمده، یک «رمز مخفی» در فرم می‌گذاریم. اگر رمز درست نبود، فرم را رد می‌کنیم.

**گام ۱ — در صفحه فرم، رمز را می‌سازیم:**

```php
<?php
session_start();

if (empty($_SESSION['csrf'])) {
    $_SESSION['csrf'] = bin2hex(random_bytes(16));
}
?>
<form action="process.php" method="post">
    <input type="hidden" name="csrf" value="<?php echo $_SESSION['csrf']; ?>">
    <label for="name">Name:</label>
    <input type="text" id="name" name="name">
    <button type="submit" name="submit">Send</button>
</form>
```

**گام ۲ — در صفحه پردازش، رمز را بررسی می‌کنیم:**

```php
<?php
session_start();

if (isset($_POST['csrf']) && $_POST['csrf'] === $_SESSION['csrf']) {
    echo "Request is valid.";
} else {
    echo "Invalid request.";
}
?>
```

**تشبیه ساده:** مثل این است که درِ اتاق مدیر یک رمز داشته باشد. هر کسی از داخل مدرسه رمز را دارد و می‌تواند بیاید. اما کسی که از بیرون مدرسه می‌آید، رمز را ندارد و نمی‌تواند وارد شود.

#### ابزار ششم: بررسی فایل آپلودی

قبل از قبول فایل، سه چیز را بررسی می‌کنیم: پسوند، حجم و نوع فایل.

**مثال کاربردی — فقط عکس قبول کنیم:**

```php
<?php
$allowed = ['jpg', 'jpeg', 'png'];
$maxSize = 2 * 1024 * 1024; // 2 MB

$ext = strtolower(pathinfo($_FILES['photo']['name'], PATHINFO_EXTENSION));
$size = $_FILES['photo']['size'];

if (!in_array($ext, $allowed)) {
    echo "Only JPG and PNG files are allowed.";
} elseif ($size > $maxSize) {
    echo "File is too large. Maximum 2 MB.";
} else {
    echo "File is OK.";
}
?>
```

### ۴. الگوی کامل و امن برای دریافت و نمایش داده

حالا همه چیز را با هم ترکیب کنیم. یک فرم نظرخواهی ساده می‌سازیم که امن باشد.

**فایل `comment.html`:**

```html
<form action="comment.php" method="post">
    <label for="name">Name:</label>
    <input type="text" id="name" name="name">

    <label for="email">Email:</label>
    <input type="email" id="email" name="email">

    <label for="comment">Comment:</label>
    <textarea id="comment" name="comment" rows="3"></textarea>

    <button type="submit" name="submit">Send</button>
</form>
```

**فایل `comment.php`:**

```php
<?php
if (isset($_POST['submit'])) {

    // گام ۱: بررسی وجود داده
    if (isset($_POST['name']) && !empty($_POST['name'])) {

        // گام ۲: پاک‌سازی فاصله‌ها
        $name = trim($_POST['name']);

        // گام ۳: ایمن‌سازی برای نمایش
        $name = htmlspecialchars($name);

        echo "Name: " . $name . "<br>";

    } else {
        echo "Name is required.<br>";
    }

    // بررسی ایمیل با فیلتر
    if (isset($_POST['email'])) {
        $email = filter_var(trim($_POST['email']), FILTER_VALIDATE_EMAIL);

        if ($email === false) {
            echo "Email is not valid.<br>";
        } else {
            echo "Email: " . htmlspecialchars($email) . "<br>";
        }
    }

    // بررسی نظر
    if (isset($_POST['comment']) && !empty($_POST['comment'])) {
        $comment = htmlspecialchars(trim($_POST['comment']));
        echo "Comment: " . $comment . "<br>";
    } else {
        echo "Comment is required.<br>";
    }

} else {
    echo "Please fill the form first.";
}
?>
```

**توضیح گام‌به‌گام این الگو:**

- **گام ۱:** بررسی می‌کنیم که داده وجود دارد.
- **گام ۲:** با `trim` فاصله‌های اضافی را حذف می‌کنیم.
- **گام ۳:** با `filter_var` درستی داده را بررسی می‌کنیم (برای ایمیل).
- **گام ۴:** با `htmlspecialchars` داده را برای نمایش ایمن می‌کنیم.
- **گام ۵:** نمایش می‌دهیم.

**اگر کاربر خرابکار کد بفرستد چه می‌شود؟**

فرض کنید در کادر نظر می‌نویسد:

```
<script>alert('hacked')</script>
```

خروجی صفحه این خواهد بود:

```
Comment: &lt;script&gt;alert('hacked')&lt;/script&gt;
```

به‌جای اجرای کد، متن ساده دیده می‌شود. حمله خنثی شد!

### ۵. پنج قاعده طلایی برای همه فرم‌ها

- **قاعده ۱:** به هیچ داده‌ای از کاربر اعتماد نکنید.
- **قاعده ۲:** برای نمایش، همیشه از `htmlspecialchars()` استفاده کنید.
- **قاعده ۳:** برای بررسی درستی، از `filter_var()` استفاده کنید.
- **قاعده ۴:** برای پایگاه داده، همیشه از پرس‌وجوی آماده استفاده کنید.
- **قاعده ۵:** برای فرم‌های حساس، توکن CSRF بگذارید.

### ۶. پیوند با موضوع قبلی

در موضوع قبلی یاد گرفتیم که بررسی کنیم داده وجود دارد یا نه. اما این کافی نیست. یک داده می‌تواند وجود داشته باشد، ولی خطرناک باشد. پس بعد از بررسی وجود، باید آن را ایمن کنیم.

**به ترتیب انجام دهید:**

- بررسی وجود (با `isset` یا `!empty`)
- پاک‌سازی (با `trim`)
- اعتبارسنجی (با `filter_var`)
- ایمن‌سازی (با `htmlspecialchars`)
- نمایش

## ده پرسش چهارگزینه‌ای

**۱.** قاعده طلایی امنیت فرم چیست؟
- الف) به هیچ داده‌ای از کاربر اعتماد نکنید
- ب) فقط از GET استفاده کنید
- پ) همه داده‌ها را با `echo` نمایش دهید
- ت) هیچ بررسی‌ای لازم نیست

**۲.** حمله XSS چه کاری انجام می‌دهد؟
- الف) پایگاه داده را حذف می‌کند
- ب) کد JavaScript را در مرورگر کاربران اجرا می‌کند
- پ) فایل آپلود می‌کند
- ت) رمز عبور را تغییر می‌دهد

**۳.** کدام تابع نویسه‌های خطرناک را بی‌خطر می‌کند و از XSS جلوگیری می‌کند؟
- الف) `trim`
- ب) `htmlspecialchars`
- پ) `isset`
- ت) `var_dump`

**۴.** اگر کاربر `<script>alert('hi')</script>` بفرستد و ما از `htmlspecialchars` استفاده کنیم، در صفحه چه دیده می‌شود؟
- الف) یک پنجره هشدار باز می‌شود
- ب) متن `<script>alert('hi')</script>` به‌صورت ساده دیده می‌شود
- پ) صفحه بسته می‌شود
- ت) هیچ چیزی دیده نمی‌شود

**۵.** کدام فیلتر برای بررسی درستی ایمیل به کار می‌رود؟
- الف) `FILTER_SANITIZE_EMAIL`
- ب) `FILTER_VALIDATE_EMAIL`
- پ) `FILTER_VALIDATE_INT`
- ت) `FILTER_VALIDATE_URL`

**۶.** `trim()` چه کاری انجام می‌دهد؟
- الف) داده را حذف می‌کند
- ب) فاصله‌های ابتدا و انتهای رشته را حذف می‌کند
- پ) رشته را به عدد تبدیل می‌کند
- ت) فایل آپلود می‌کند

**۷.** حمله SQL Injection چیست؟
- الف) حمله‌ای که کد JavaScript در صفحه اجرا می‌کند
- ب) حمله‌ای که دستور مخرب در پایگاه داده تزریق می‌کند
- پ) حمله‌ای که فایل آپلود می‌کند
- ت) حمله‌ای که کوکی‌ها را می‌دزدد

**۸.** برای جلوگیری از SQL Injection چه کار باید کرد؟
- الف) داده را با `echo` نمایش دهیم
- ب) از پرس‌وجوی آماده (Prepared Statement) استفاده کنیم
- پ) داده را با `trim` پاک کنیم
- ت) از GET استفاده کنیم

**۹.** توکن CSRF برای چه کاری به کار می‌رود؟
- الف) جلوگیری از XSS
- ب) جلوگیری از تزریق SQL
- پ) جلوگیری از ارسال فرم از سایت‌های دیگر
- ت) جلوگیری از آپلود فایل

**۱۰.** برای امنیت آپلود فایل، کدام مورد لازم است؟
- الف) بررسی پسوند، حجم و نوع فایل
- ب) ذخیره فایل با نام اصلی
- پ) ذخیره فایل در پوشه اجرایی PHP
- ت) اجازه دادن به همه پسوندها
