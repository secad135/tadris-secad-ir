# متد POST: ارسال داده در بدنه درخواست

## خلاصه مطالب

### ۱. متد POST چیست؟

`POST` دومین روش اصلی ارسال داده از فرم به سرور است. در این روش، داده‌های فرم **در بدنه درخواست** فرستاده می‌شوند، نه در نشانی صفحه. به زبان ساده: **داده‌ها داخل یک «پاکت» گذاشته می‌شوند و پاکت به سرور می‌رود؛ از بیرون دیده نمی‌شوند.**

در متد GET داده‌ها روی نشانی سوار می‌شدند و همه آن‌ها را می‌دیدند. در POST داده‌ها در بدنه درخواست هستند و در نوار آدرس مرورگر دیده نمی‌شوند.

پس ویژگی اصلی POST این است: **داده‌ها در نشانی صفحه نیستند و از دید کاربر پنهان‌اند.**

### ۲. داده‌ها کجا می‌روند؟

وقتی فرمی با `method="post"` ارسال می‌شود، مرورگر داده‌ها را به شکل «نام=مقدار» آماده می‌کند و آن‌ها را در بخشی از درخواست به نام **بدنه (Body)** می‌گذارد. این بدنه همراه درخواست به سرور می‌رود، اما در نوار آدرس نمایش داده نمی‌شود.

برای همین، اگر فرم POST ارسال شود، نشانی صفحه تغییر نمی‌کند. فقط نام صفحه مقصد (مثلاً `process.php`) در نوار آدرس دیده می‌شود، بدون هیچ داده‌ای در انتهای آن.

**نمونه ساده:**

```html
<form action="process.php" method="post">
    <label for="username">Username:</label>
    <input type="text" id="username" name="username">
    <button type="submit">Send</button>
</form>
```

اگر کاربر عبارت `Ali` را وارد کند و دکمه را بزند، مرورگر داده را در بدنه درخواست به `process.php` می‌فرستد. نوار آدرس فقط `process.php` را نشان می‌دهد، بدون `?username=Ali`.

### ۳. دیدن آرایه `$_POST` با `var_dump` (گام اول یادگیری)

PHP داده‌های POST را در آرایه‌ای به نام `$_POST` نگه می‌دارد. کلیدهای این آرایه، همان مقدار `name` ورودی‌ها هستند. برای دیدن محتوای آن، از `var_dump()` استفاده می‌کنیم.

**گام ۱ — فایل `process.php` را می‌سازیم:**

```php
<?php
var_dump($_POST);
?>
```

**گام ۲ — فرم را در مرورگر باز می‌کنیم، پر می‌کنیم و ارسال می‌کنیم.**

فرض کنید فرمی با دو ورودی داریم: `username` و `age`. اگر کاربر `Ali` و `15` وارد کند، خروجی چنین است:

```
array(2) {
  ["username"]=>
  string(3) "Ali"
  ["age"]=>
  string(2) "15"
}
```

**این خروجی چه می‌گوید؟**

- `array(2)` یعنی آرایه دو عضو دارد.
- `["username"]` و `["age"]` کلیدهای آرایه‌اند (همان `name` ورودی‌ها).
- `string(3) "Ali"` یعنی مقدار `Ali` یک رشته است.
- `string(2) "15"` یعنی مقدار `15` هم **رشته** است، نه عدد. همان نکته GET: هر چیزی که از فرم بیاید، در PHP رشته است.

اگر فرم فقط یک ورودی داشته باشد، آرایه یک عضو دارد. اگر هیچ داده‌ای فرستاده نشود (مثلاً صفحه مستقیم باز شود)، خروجی چنین است:

```
array(0) {
}
```

**نکته کاربردی:** همیشه قبل از استفاده از `$_POST`، با `var_dump` ببینید چه داده‌ای رسیده است. این کار مثل «چراغ‌قوه» است.

### ۴. خواندن داده‌ها از `$_POST`

خواندن داده ساده است. کافی است بنویسیم `$_POST['نام']` و مقدار را برداریم.

```php
<?php
$username = $_POST['username'];
echo "Hello " . $username;
?>
```

اگر کاربر `Ali` فرستاده باشد، خروجی `Hello Ali` است.

**دو نکته ساده:**

- مقدار رسیده همیشه **رشته (string)** است.
- اگر آن کلید وجود نداشته باشد، دسترسی مستقیم ممکن است هشدار (Warning) ایجاد کند. برای پیشگیری، با `isset()` بررسی می‌کنیم:

```php
<?php
if (isset($_POST['username'])) {
    $username = $_POST['username'];
    echo "Hello " . $username;
} else {
    echo "No username provided.";
}
?>
```

`isset()` بررسی می‌کند آیا این کلید در آرایه وجود دارد یا نه.

**یک نکته مهم درباره بررسی ارسال فرم:** برای اینکه بدانیم اصلاً فرم ارسال شده است یا نه، معمولاً روی دکمه ثبت یک `name` می‌گذاریم و وجود آن را بررسی می‌کنیم. مثلاً:

```html
<button type="submit" name="submit">Send</button>
```

و در PHP:

```php
<?php
if (isset($_POST['submit'])) {
    echo "Form was submitted.";
} else {
    echo "Please fill the form.";
}
?>
```

این روش ساده و رایج است و کمک می‌کند کد PHP فقط وقتی فرم ارسال شده اجرا شود.

### ۵. ویژگی‌های متد POST

**الف) داده‌ها در نوار آدرس دیده نمی‌شوند.** کاربر داده‌ها را در نشانی نمی‌بیند. این ویژگی برای داده‌های محرمانه بسیار مهم است.

**ب) محدودیت طول نشانی ندارد.** چون داده‌ها در نشانی نیستند، محدودیت ۲۰۰۰ نویسه‌ای نشانی مشکلی ایجاد نمی‌کند. POST برای فرستادن حجم زیاد داده (مثلاً متن طولانی یا فایل) مناسب است. (البته سرور تنظیماتی برای حداکثر حجم دارد، ولی این محدودیت مربوط به نشانی نیست.)

**پ) قابل نشانک‌گذاری نیست.** چون داده‌ها در نشانی نیستند، نمی‌توان نتیجه یک فرم POST را در نشانک‌ها ذخیره کرد. اگر صفحه را دوباره باز کنید، داده‌ها همراه نمی‌آیند.

**ت) در تاریخچه مرورگر ذخیره نمی‌شود.** نشانی‌های POST در تاریخچه مرورگر ذخیره نمی‌شوند (چون داده‌ای در نشانی نیست).

**ث) می‌تواند وضعیت سرور را تغییر دهد.** POST برای **تغییر** اطلاعات ساخته شده است: ثبت‌نام، ورود، ذخیره داده، حذف، ویرایش.

**ج) با بازخوانی صفحه تکرار نمی‌شود.** اگر بعد از ارسال فرم POST، صفحه را بازخوانی کنید، مرورگر هشدار می‌دهد که داده دوباره فرستاده شود یا نه. این رفتار از ثبت تکراری جلوگیری می‌کند.

### ۶. موارد کاربرد متد POST

POST جایی مناسب است که داده حساس باشد یا عملیات تغییر ایجاد کند:

- **فرم ورود و ثبت‌نام:** رمز عبور نباید در نشانی دیده شود.
- **فرم تماس با ما:** پیام کاربر باید به سرور برود و ثبت شود.
- **ذخیره یا ویرایش اطلاعات:** مثلاً ثبت نمره، ویرایش پروفایل.
- **آپلود فایل:** ارسال فایل از طریق فرم همیشه با POST انجام می‌شود.
- **ارسال حجم زیاد داده:** مثلاً متن طولانی.

### ۷. مثال کامل و ساده

فرض کنید صفحه‌ای برای ثبت نام دانش‌آموز در یک کلاس تابستانی داریم.

**فایل `register.html`:**

```html
<form action="register.php" method="post">
    <label for="fullname">Full Name:</label>
    <input type="text" id="fullname" name="fullname">

    <label for="age">Age:</label>
    <input type="number" id="age" name="age" min="10" max="20">

    <button type="submit" name="submit">Register</button>
</form>
```

**فایل `register.php` — گام اول: ببینیم چه رسیده است**

```php
<?php
var_dump($_POST);
?>
```

اگر کاربر `Sara` و `14` وارد کند و دکمه را بزند، خروجی:

```
array(3) {
  ["fullname"]=>
  string(4) "Sara"
  ["age"]=>
  string(2) "14"
  ["submit"]=>
  string(0) ""
}
```

سه عضو داریم: `fullname`، `age` و `submit`. عضوی که `submit` نام دارد، از دکمه ثبت آمده و مقدارش رشته خالی است (چون روی دکمه `value` ننوشتیم).

**فایل `register.php` — گام دوم: از داده‌ها استفاده کنیم**

```php
<?php
if (isset($_POST['submit'])) {
    if (isset($_POST['fullname'])) {
        $fullname = $_POST['fullname'];
        echo "Name: " . $fullname . "<br>";
    }

    if (isset($_POST['age'])) {
        $age = (int) $_POST['age'];
        echo "Age: " . $age . "<br>";
    }
} else {
    echo "Please fill the form first.";
}
?>
```

**توضیح گام‌به‌گام:**

- اول با `isset($_POST['submit'])` بررسی کردیم که فرم ارسال شده است. اگر صفحه مستقیم باز شود، این شرط برقرار نیست و پیام مناسب نشان داده می‌شود.
- سپس برای هر داده، با `isset()` بررسی کردیم که وجود دارد.
- مقدار `age` را با `(int)` به عدد تبدیل کردیم، چون از POST همه چیز رشته می‌آید.
- در نوار آدرس مرورگر فقط `register.php` دیده می‌شود، بدون هیچ داده‌ای.

### ۸. نکات امنیتی ساده درباره POST

- **POST داده را از نوار آدرس پنهان می‌کند، ولی امنیت کامل نمی‌دهد.** برای امنیت واقعی باید از پروتکل HTTPS استفاده شود. بدون HTTPS، داده‌ها در مسیر شبکه قابل دیدن هستند.
- **به داده‌های `$_POST` اعتماد نکنید.** کاربر می‌تواند داده را دستکاری کند (مثلاً با ابزارهای مرورگر). پس داده‌ها باید بررسی شوند.
- **POST را با تغییر داده ترکیب کنید.** در واقع POST برای تغییر ساخته شده است؛ اما پیش از هر تغییری، داده را بررسی و ایمن کنید.

**نکته درباره امنیت نمایش داده:** پیش از نمایش هر داده‌ای که از کاربر آمده، باید آن را ایمن کنیم. تابع مناسب این کار در بخش «توابع پیش‌ساخته» به‌طور کامل معرفی و تمرین خواهد شد.

## ده پرسش چهارگزینه‌ای

**۱.** در متد POST، داده‌های فرم کجا قرار می‌گیرند؟
- الف) در انتهای نشانی صفحه
- ب) در بدنه درخواست
- پ) در کوکی
- ت) در یک فایل جداگانه

**۲.** اگر فرمی با `method="post"` ارسال شود، نوار آدرس مرورگر چه چیزی نشان می‌دهد؟
- الف) همه داده‌ها را
- ب) فقط نام صفحه مقصد را، بدون داده‌ها
- پ) هیچ چیزی، حتی نام صفحه را
- ت) داده‌ها را به شکل `?name=value`

**۳.** کدام آرایه، داده‌های ارسال‌شده با POST را نگه می‌دارد؟
- الف) `$_GET`
- ب) `$_SESSION`
- پ) `$_POST`
- ت) `$_FILES`

**۴.** برای دیدن محتوای آرایه `$_POST` از کدام تابع استفاده می‌کنیم؟
- الف) `echo`
- ب) `print`
- پ) `var_dump`
- ت) `count`

**۵.** اگر کاربر در فرم POST مقدار عددی `15` وارد کند، نوع مقدار `"15"` در آرایه `$_POST` چیست؟
- الف) عدد صحیح (int)
- ب) عدد اعشاری (float)
- پ) رشته (string)
- ت) بولین (bool)

**۶.** کدام تابع بررسی می‌کند که آیا یک کلید در آرایه `$_POST` وجود دارد یا نه؟
- الف) `var_dump`
- ب) `isset`
- پ) `echo`
- ت) `count`

**۷.** کدام کاربرد برای متد POST مناسب‌تر است؟
- الف) جستجو در فهرست کتاب‌ها
- ب) صفحه‌بندی نتایج
- پ) ثبت‌نام کاربر جدید
- ت) ساختن نشانی قابل اشتراک‌گذاری

**۸.** کدام گزاره درباره متد POST درست است؟
- الف) داده‌ها در نوار آدرس دیده می‌شوند
- ب) محدودیت طول نشانی دارد
- پ) نتیجه‌اش قابل نشانک‌گذاری نیست
- ت) برای خواندن اطلاعات ساخته شده است

**۹.** اگر بخواهیم بدانیم اصلاً فرم POST ارسال شده است یا نه، ساده‌ترین راه کدام است؟
- الف) وجود یک `name` روی دکمه ثبت و بررسی آن با `isset`
- ب) بررسی نوار آدرس مرورگر
- پ) استفاده از `echo` در بالای صفحه
- ت) هیچ راهی وجود ندارد

**۱۰.** کدام گزاره درباره امنیت POST درست است؟
- الف) POST داده را کاملاً امن می‌کند
- ب) POST داده را از نوار آدرس پنهان می‌کند، ولی برای امنیت واقعی HTTPS لازم است
- پ) POST داده‌ها را رمزنگاری می‌کند
- ت) POST نیازی به بررسی داده ندارد
